# DSH profile restore

Restore a profile's declarative payload from
`<repo>/backup/profiles/<profile>/` into `$DSH_HOME/profiles/<profile>/`
(default `~/.dsh`). This skill is the repository's only sanctioned writer of
live profile files (see AGENTS.md).

## Steps

1. **Read the backup**: `package.json`, `cordis.patch.yml`, `meta.json`.
   Report the recorded `createdDshVersion` and `lastUpdatedDshVersion` to the
   user before touching anything.
2. **Preflight diff**: if the target profile directory exists, diff the
   current files against the backup (both `package.json` and
   `cordis.patch.yml`) and show a concise summary. Never overwrite silently.
3. **Confirm** with ask_user_question, naming exactly which two files will be
   written into which directory. Abort on decline or ambiguity.
4. **Write**: create the target profile directory if missing, then write
   `package.json` and `cordis.patch.yml` byte-for-byte from the backup.
   Never delete or modify any other file: `node_modules`,
   `pnpm-workspace.yaml`, and `cordis.yml` are left alone (the last is
   regenerated by DSH on every boot).
5. **Report post-conditions**:
   - If this session runs the target profile (`$env:DSH_PROFILE`), note that
     `cordis.patch.yml` edits can hot-apply (`patchReload: live`), but
     `package.json` bundle-list changes take effect after a DSH restart.
   - If the restored manifest lists bundles not installed on this machine,
     tell the user to install them via `plugin_manager` `install_bundle`
     (never run pnpm inside the profile by hand).
   - Suggest re-running `dsh-profile-backup` afterwards so `meta.json`
     reflects the restored state.

## Rules

- Write only the two payload files, and only after explicit confirmation.
- Never run a package manager inside the profile directory.
- If backup and current files are already identical, report that and skip
  the confirmation entirely.
